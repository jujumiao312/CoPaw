## 1. 功能概述

| 项 | 内容 |
|---|---|
| 功能 ID | CAP-001 |
| 名称 | claw技能运行看板（页面标题：Claw 技能运行看板） |
| 别名 | Claw 技能运行看板、claw技能运行看板、金葵花任务类型报表、task-type report |
| 菜单 i18n key | `nav.analyticsClawSkillDataOverview`（`console/src/locales/zh.json:73`） |
| 所属工程 | 前端 `console/`，后端 `monitor/` |
| 后端业务名称 | 金葵花任务类型报表（task-type report） |

**业务目标**：面向招商银行金葵花客户经营场景，按 **机构（分行/支行）、客户经理、技能** 维度，统计三类客户经营任务（推送名单+方案、推送仅方案、主动提问）在技能维度的运行表现与经营转化指标，支撑运营/管理层评估技能运行质量与业绩贡献。

**解决的业务问题**：把分散在明细表（`swe_cron_executions` / `swe_cron_subtasks` / `swe_tracing_spans` / `swe_html_preview_click_events`）中的运行数据，聚合为「机构 × 客户经理 × 技能 × 任务类型」指标，避免实时扫描明细表。2026-09 起引入预聚合落盘快照表 `swe_rm_claw_list_ind_stat`（高斯 → TDSQL），前端已切换到快照接口。

**主要用户**：业务系统（iframe 嵌入 Console）中的运营/管理层用户；身份通过请求头 `X-Bbk-Id`（分行）与 `X-Source-Id`（来源）区分。

## 2. 功能边界

### 2.1 包含的能力
- 4 个统计维度：`branch`（分行）、`org`（支行）、`manager`（客户经理）、`skill`（技能）。
- 3 类任务类型：`push_plan`（推送名单+方案）、`push_other`（推送仅方案）、`ask_plan`（主动提问）。
- 支行类型（仅 `org` 维度）：`zero_special`（零专支行，默认）/ `frs`（综合支行），无「全部」。
- 9 种落盘组合（`rpt_combo`）：`overall` / `branch` / `org` / `org_frs` / `manager` / `branch_skill` / `org_skill` / `org_frs_skill` / `manager_skill`（`skill` 维度复用 `manager_skill`；`org_frs`/`org_frs_skill` 为综合支行组合）。
- 主查询、机构/技能下拉选项、可用跑数日期、批次状态核对、全量 XLSX 导出。
- 技能明细下钻（点击「技能总数」展开）。
- 服务端分页（manager/skill 维度）与客户端切片（branch/org 维度）。

### 2.2 不包含的能力
- ❌ 数据装载：预聚合表由现场作业从高斯写入 TDSQL，本仓库不提供装载脚本（⚠️ 用户确认：此部分不处理）。
- ❌ 实时明细统计：在线接口仍保留，但前端已切换到快照接口。
- ❌ 技能「调用次数排行榜」：属于 tracing 模块独立功能（`monitor/src/monitor/app/routers/tracing.py:907`），与本功能不是同一功能。

## 4. 业务流程

### 4.1 主查询
1. 用户选择：统计日期（T-1 上限）、统计维度、任务类型、分行/支行/技能、客户经理关键字。
2. 前端 `useReport` 发起 `GET /api/monitor/report/task-type`（manager/skill 维度带 `page/page_size`）。
3. 后端 `TaskTypeSnapshotService.get_report` 完成「分行收窄 → 批次校验 → 名称解析 → 筛选 → 分页/截断 → 权限人数实时统计 → 行装配」。
4. 前端渲染统计表；非技能维度显示「技能总数」列，点击下钻技能明细。

### 4.2 技能明细下钻
- 用户点击某行「技能总数」→ `SkillDetails` 以 `skill_detail=true` 重新查询（限定该机构/客户经理），展示关联技能运行情况。

### 4.3 导出
- `ReportExport` → `GET /api/monitor/report/task-type/export`（必须指定 `task_type`，不能传分页），后端 openpyxl 生成 XLSX，前端校验 content-type 后触发下载。

### 4.4 日期与选项
- 页面初始化 `getTaskReportDates`（`/task-type/dates`）取可用跑数日期，默认选中 `latest_ready_prt_dt` 与 T-1 较早者。
- 分行/支行/技能下拉通过 `/task-type/options` 按 `kind` 加载。

## 5. 业务规则

### 5.1 核心规则（✅ 已验证）
1. **区间约束**：落盘快照只支持「当月 1 号 ~ 跑数日期」（`start_date` 缺省取当月 1 号；其他区间 422）。任意区间须用在线接口。（`SnapshotReportParams.validate_snapshot_scope`）
2. **日期上限 T-1**：可选统计日期不超过 `dayjs().subtract(1,'day')`；默认取「最近快照日 与 T-1 较早者」。（`taskTypeReport.ts`）
3. **分行权限**：`X-Bbk-Id` 非 `100` 时强制 `first_bbk_id` 收窄；显式查询其他分行 → 403 `report_scope_forbidden`。（`enforce_branch`）
4. **维度组合映射**：`(group_by, skill_detail, org_type)` → `rpt_combo`；`group_by=skill` 复用 `manager_skill`（行按 客户经理 × 技能 展开）；`org_type` 仅对 `group_by=org` 生效（`zero_special`→`org`/`org_skill`，`frs`→`org_frs`/`org_frs_skill`）。（`combo_of` / `COMBO_MAP`）
5. **筛选必须匹配组合**：筛选维度不在组合内 → 422 `report_filter_not_supported`。（`validate_filter_scope`）
6. **分页约束**：`page/page_size` 成对、仅 manager/skill 维度且指定 `task_type`；`page_size` 1..100。
7. **keyword 约束**：仅 manager/skill 维度；匹配 `user_name/user_id/pst_lvl`（LIKE 通配符转义）。
8. **skill_name 约束**：仅 `group_by=skill`，按 `skill_nm` 精确匹配。
9. **`'ALL'`/空串还原**：落盘表对「本组合用不到的维度」写 `'ALL'` → 接口还原 `null`；空串表示「名单缺机构号」真实分组，保留。（`_text`/`_dim`）
10. **技能明细不可相加**：多技能任务/客户会重复归入各技能行（warning `skill_rows_not_additive`）。
11. **技能行过滤**：技能明细/技能维度只保留 `suc_execute_job <> 0` 的行；汇总不过滤。（`build_filters`）
12. **主查询不过滤技能总数**（2026-10-21 起）：技能总数为 0 的行也返回（分页 total 与导出一致）；技能下拉 options 仍过滤 `skill_cnt <> 0`。
13. **有权限客户经理数读落盘列**：仅 overall/branch/org 汇总返回，直接读落盘 `auth_manager_cnt`（2026-11-23 起不再实时计算，`_fetch_permission_counts` 已删除）；manager/skill/技能明细返回 `null`。
14. **比例口径**：百分比数值（百分点）；零分母 → `null`；期间比率非队列转化率，可能 >100%（warning `period_ratios_not_cohort_conversion`）。
15. **截断与导出上限**：非分页主查询上限 200000 行（warning `report_rows_truncated`）；导出上限 50000 行 → 413 `report_export_too_large`。
16. **无快照**：`prt_dt + source_id` 无行 → 404 `report_snapshot_not_found`（前端映射为空态）。
17. **名称歧义**：机构名称对应多个机构 → 422 `organization_name_ambiguous`。
18. **指标适用范围**：`active_task_count/paused_task_count` 仅 manager/skill 维度；`skill_count` 仅非技能维度；`permission_manager_count/active_manager_count` 仅非 manager/skill 维度；`new_task_manager_count` 仅 branch/org 维度；`total_execute_job` 4 维度均展示但仅 `push_plan` 有值（其余任务类型为 `null`）。
19. **支行类型约束**：`org_type` 取 `zero_special`（默认）/ `frs`，无「全部」，非法值 422 `report_validation_error`；仅 `group_by=org` 维度生效，其余维度忽略。
20. **综合支行列映射**：`org_frs`/`org_frs_skill` 组合下逻辑 `org_id`/`org_nm` 映射物理 `frs_brn_org_id`/`frs_brn_org_nm`；零专仍映射 `brn_org_id`/`brn_org_nm`。（`COLUMN_MAP` / `_physical_column`）
21. **综合支行选项与名称解析**：`org_type=frs` 时 `options?kind=orgs` 与机构名称解析/范围校验均从落盘表 `org_frs` 组合按 `frs_brn_org_id` 去重，不依赖 `jkh_user_inf`（分行名称仍走 `jkh_user_inf`）。

### 5.2 指标口径（源自 `DESIGN.md`「十四字段矩阵」与前端 `leadingMetrics`）

> 表中第 1 行 `skill_count` 为维度字段；其余 16 项为运行指标（与前端 `index.tsx` 的 `leadingMetrics` 一致，含 2026-11-23 新增的 `new_task_manager_count`/`total_execute_job`）。

| 指标 | 含义 | 要点 |
|---|---|---|
| `skill_count` | 技能总数 | 非技能维度；关联统计技能 DISTINCT |
| `permission_manager_count` | 有权限客户经理人数 | 读落盘 `auth_manager_cnt`（见规则 13），不再实时计算 |
| `new_task_manager_count` | 有推送任务客户经理人数 | 仅 branch/org 维度；读落盘 `new_task_manager_cnt` |
| `active_manager_count` | 活跃客户经理人数 | 推送类任务 owner 去重；ask 为 null |
| `total_execute_job` | 总推送任务数 | 4 维度均展示；读落盘 `total_execute_job`，仅 `push_plan` 有值 |
| `suc_execute_job` | 成功执行任务数 | push 按 success 执行；ask 按合格 Span `COUNT(DISTINCT trace_id)` |
| `read_tasks` | 已查看任务数 | push 按 `is_read=1`；ask 等于成功数 |
| `read_rate` | 任务查看率 | read_tasks / suc_execute_job × 100 |
| `recommended_customers` | 客户级方案数 | DISTINCT custuid；push_other 为 null |
| `read_customer_count` | 已查看客户级方案数 | 点击事件 DISTINCT customer_id |
| `plan_read_rate` | 客户级方案查看率 | read_customer_count / recommended_customers × 100 |
| `insight_customer_count` | 点击跳转客户洞察客户数 | DISTINCT customer_id |
| `click_to_insight_rate` | 洞察覆盖率 | insight_customer_count / recommended_customers × 100 |
| `insight_count` | 点击客户洞察总次数 | 事件总行数 |
| `phone_customer_count` | 点击跳转电访客户数 | DISTINCT customer_id |
| `click_to_phone_rate` | 电访覆盖率 | phone_customer_count / recommended_customers × 100 |
| `phone_count` | 点击去电访总次数 | 事件总行数 |

> 另含转化指标：`vld_ctc_cust_qty` / `vld_ctc_cust_rate` + 11 项经营指标 × `_t1/_t3/_t7/_t14`（财富/基金购买、AUM、金葵花提升、中收等），前端 `index.tsx` 的 `statMetrics` 定义。

```

[后端] FastAPI app (_app.py, prefix /api)
  → api_router (routers/__init__.py 挂载 task_type_snapshot_router)
    → router prefix /monitor/report, 端点 GET /task-type
      → task_type_snapshot_report (routers/task_type_snapshot.py)

          → enforce_branch（X-Bbk-Id 分行收窄）
```
